    1. Add Vendor (KYC)

    Route

    POST /vendor/addvendor

    Description

    Creates a new vendor with comprehensive KYC (Know Your Customer) information including document uploads for registration certificate, PAN card, cancelled cheque, and company logo. Documents are processed individually using specialized upload handlers for better error handling and control.

    Request Body

    • Content-Type: multipart/form-data
    • File Fields:
      • registration_certificate: PDF/Image file (optional)
      • pan_upload: PDF/Image file (optional)
      • cancelled_cheque: PDF/Image file (optional)
      • logo_upload: PDF/Image file (optional)
    • Form Fields:
      • STOKEN: Session token
      • querystring: Encrypted data containing vendor KYC details

    Decrypted Querystring Data

    { "vendorname": "JK Construction", "address": "123 Main Street, Coimbatore", "state": "Tamil Nadu", "pincode": "641001", "contactpersonname": "John Doe", "contactpersondesignation": "Manager", "contactpersonphone": "8393923242", "email": "jk@gmail.com", "businesstype": "Manufacturer", "yearofestablishment": 2010, "gstnumber": "33ABCD43wsd123", "pannumber": "ABCPD1234E", "annualturnover": 50000000.00, "productsservices": "Construction materials, cement, steel", "hsnsaccode": "2523,7207", "description": "Leading manufacturer of construction materials", "bankname": "State Bank of India", "branchname": "Coimbatore Main", "accountnumber": "1234567890", "ifsccode": "SBIN0001234", "isocertification": "ISO 9001:2015", "othercertifications": "BIS certification for cement" }

    Response Body

    Success Response

    { "code": true, "message": "Vendor Added Successfully", "Value": { "vendorid": 1, "registration_certificate_uploaded": true, "pan_upload_uploaded": true, "cancelled_cheque_uploaded": true, "logo_uploaded": true } }

    Error Response

    { "code": false, "message": "Error message describing the issue", "Value": "ADD VENDOR" }

    Required Fields

    Field Type Required Description
    vendorname String Yes Vendor company name
    contactpersonphone String Yes Contact person phone number
    email String Yes Vendor email address
    businesstype Enum Yes Manufacturer/Distributor/Service Provider/Others
    yearofestablishment Year Yes Year company was established
    gstnumber String Yes GST registration number
    pannumber String Yes PAN card number
    annualturnover Decimal Yes Annual turnover in INR
    productsservices Text Yes List of products/services offered
    hsnsaccode String Yes HSN/SAC codes
    bankname String Yes Bank name for payments
    branchname String Yes Bank branch name
    accountnumber String Yes Bank account number
    ifsccode String Yes Bank IFSC code

    Optional Fields

    • address: Company address
    • state: State/Province
    • pincode: Postal/ZIP code
    • contactpersonname: Contact person name
    • contactpersondesignation: Contact person designation
    • description: Company description
    • isocertification: ISO certification details
    • othercertifications: Other certifications

    File Upload Requirements

    • Format: PDF, JPG, PNG, JPEG
    • Size: Maximum 5MB per file
    • Storage: /filestorage/YYYY/Month/DD/VendorKYC/{DocumentType}/
    • Fields: registration_certificate, pan_upload, cancelled_cheque, logo_upload (all optional)
    • Processing: Each document type is processed individually with dedicated upload handlers
    • Storage Folders:
      • registration_certificate → RegistrationCertificate/
      • pan_upload → PAN/
      • cancelled_cheque → CancelledCheque/
      • logo_upload → Logo/

    8. Vendor Details Preloader (RFQ ID Generator)

    Route

    POST /vendor/detailspreloader

    Description

    Generates a unique RFQ ID for creating new RFQ processes.

    Request Body

    { "STOKEN": "your_session_token_here" }

    Response Body

    Success Response

    { "code": true, "message": "RFQ ID generated successfully", "rfq_id": "SSIPL-RFQ/2507/01" }

    Error Response

    { "code": false, "message": "Error message describing the issue", "rfq_id": null }

    RFQ ID Format

    • Pattern: SSIPL-RFQ/{YYMM}/{counter}
    • YYMM: Year-Month (e.g., 2507 for July 2025)
    • Counter: 2-digit sequential number (01, 02, etc.)
    • Generated By: Gen_vendor_rfqId stored procedure
    • Storage: vendor_rfq_ids table

    11. Post RFQ

    Route

    POST /vendor/postrfq

    Description

    Posts an RFQ to a vendor including PDF upload, database storage, and email notification.

    Request Body

    • Content-Type: multipart/form-data
    • File Field: file (PDF file, max 10MB)
    • Form Fields:
      • STOKEN: Session token
      • querystring: Encrypted data containing RFQ details

    Decrypted Querystring Data

    { "vendorname": "JK Constructiond", "vendorid": 1, "GSTIN": "33AATFN1941J1Z0", "PAN": "NAEPK8086H", "Contact_person": "Ravi Kumar", "vendoraddress": "Chinnverampatti, Udumallai", "product": [ { "productsno": 1, "productname": "Mechanical Keyboard", "productquantity": 8 }, { "productsno": 2, "productname": "keyboard", "productquantity": 4 } ], "notes": ["6ythgnb"], "messagetype": 3, "feedback": "", "title": "656", "emailid": "jk@gmail.com", "phoneno": "9344268155", "date": "2025-07-07 13:53:14.216385", "rfqgenid": "SSIPL-RFQ/250740", "ccemail": "" }

    RFQ Storage Fields (stored in vendor_rfq_details table)

    Note: All vendor and product details are stored directly from the querystring parameters in a single table with JSON columns for products and notes.

    • rfqgenid: RFQ Generation ID (e.g., SSIPL-RFQ/250740)
    • vendor_id: Vendor ID (for reference)
    • vendor_name: Vendor company name
    • gstin: GST identification number
    • pan: PAN card number
    • contact_person: Contact person name
    • vendor_address: Vendor address
    • title: Title or reference number
    • email_id: Vendor email address
    • phone_no: Contact phone number
    • cc_email: CC email address
    • message_type: Message delivery type (1=email, 2=WhatsApp, 3=both)
    • feedback: RFQ feedback text
    • rfq_date: RFQ creation date and time
    • notes: JSON array of note IDs
    • products: JSON array of product details with productname, productquantity, etc.
    • notes: RFQ notes or feedback
    • created_at/updated_at: Timestamps (auto-generated)

    Notes Storage (vendor_notesmaster table)

    Note: If notes are provided in the RFQ, they are stored separately in the vendor_notesmaster table. Duplicate notes are automatically prevented - if the same note content already exists in the database, it will not be inserted again.

    • notes_id: Auto-generated primary key
    • notes: RFQ notes content (checked for duplicates)
    • row_updated_date: Timestamp (auto-generated)
    • status: 1 (active)
    • deleted_flag: 0 (not deleted)

    Message Type Options

    • 1: Email only (default)
    • 2: WhatsApp only
    • 3: Both email and WhatsApp

    Response Body

    Success Response

    { "code": true, "message": "RFQ Posted Successfully", "Value": { "vprocess_id": 1, "process_id": 2, "vendor_name": "JK constructiond", "rfq_id": "SSIPL-RFQ/250740", "emailsent": true, "whatsappsent": false, "messagetype": 1 } }

    Error Response

    { "code": false, "message": "Error message describing the issue", "Value": "POST RFQ" }

    Process Flow

    1. File Upload: PDF saved to /filestorage/YYYY/Month/DD/PostRFQ/
    2. Vendor Authentication: Validates vendor exists and is active
    3. RFQ Details Storage: Creates record in vendor_rfq_details table using values from querystring parameters (not fetched from vendors table)
    4. Notes Storage: If notes are provided, creates record in vendor_notesmaster table
    5. Database Storage:
      • Creates record in vendorprocessmaster
      • Creates record in vprocesslist
    6. Message Type Processing:
      • messagetype 1: Email only
      • messagetype 2: WhatsApp only
      • messagetype 3: Both email and WhatsApp
    7. Email Notification (if messagetype 1 or 3):
      • Sends RFQ email to vendor using VENDORRFQ template
      • Includes PDF attachment
      • Uses module tag VENDORRFQ for email settings
      • Supports CC email functionality
    8. WhatsApp Notification (if messagetype 2 or 3):
      • Sends PDF via WhatsApp to vendor's phone number
      • Uses external API (192.168.0.165:4444/billing/sendpdf)
      • Supports multiple phone numbers (comma-separated)
      • Uses feedback message for WhatsApp content
    9. Response Status:
      • Returns emailsent status (true/false)
      • Returns whatsappsent status (true/false)
      • Includes messagetype used for transparency

    Required Fields

    • rfq_id: Valid RFQ ID (generated from preloader)
    • vendorid: Valid vendor ID

    Optional Fields

    • cc_email: CC email address
    • notes: Additional notes for email
    • feedback: WhatsApp message text
    • messagetype: 1 (email), 2 (WhatsApp), 3 (both) - defaults to 1
    • product_name: Name of the product being requested
    • product_quantity: Quantity of the product being requested

    File Requirements

    • Format: PDF recommended
    • Size: Maximum 10MB
    • Storage: /filestorage/YYYY/Month/DD/PostRFQ/

    14. Authentication

    All endpoints require a valid session token (STOKEN) that:

    • Must be between 30-50 characters in length
    • Is validated against the database using SP_STOKEN_CHECK stored procedure
    • First 16 characters are used as encryption key for querystring data

    15. Security

    • Encrypted Communication: All sensitive data in querystring is encrypted using AES encryption
    • Session Validation: Session tokens are validated on every request using SP_STOKEN_CHECK stored procedure
    • File Upload Security:
      • File uploads are restricted by size (5MB max for KYC documents)
      • File type validation for documents (PDF, JPG, PNG, JPEG)
      • Files stored with timestamp prefixes to prevent naming conflicts
      • Organized folder structure by date and document type
    • SQL Injection Protection: Parameterized queries used throughout all database operations
    • Document Security:
      • KYC documents stored in secure file system locations
      • Document access controlled through API authentication
      • Binary conversion for secure document transmission
    • Data Validation: Comprehensive validation for all KYC fields including business type enum validation

    KYC Security Features

    • Document Integrity: Files are stored with original names plus timestamps
    • Access Control: All document operations require valid session tokens
    • Audit Trail: Created/updated timestamps for all vendor records
    • Secure Storage: Documents organized in date-based folder hierarchy
    • Binary Encoding: Documents converted to base64 for secure API transmission

    16. Error Handling

    Common error scenarios:

    • Authentication Errors:
      • Invalid or missing session token
